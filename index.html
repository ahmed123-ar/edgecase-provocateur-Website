Tests that only check the happy path




A traceback tells you what happened. It doesn’t tell you which assumption was wrong.


Students try a few normal lists, some positive numbers, a short string. Then hidden tests bring the empty list and the None. Beginners often don’t know which cases to try at all.


Edgecase-Provocateur generates those cases from a single example call, shows the exact failing line, and asks a question that makes you decide how the function should behave.







Four ways it helps you look


Every output is designed for the place you’re working: the terminal, a notebook, or your own code.




Notebook table
End a Jupyter cell with analyze(f, …) and get a colour-coded table of every crash.


numbers = []         IndexError
numbers = [None]     TypeError
['edgecase_probe']   TypeError


Per-probe timeout
Each probe gets 2 seconds by default. An infinite loop becomes a TimeoutError instead of a frozen program.


count_down(n = -1)
TimeoutError  after 2.00s


Silent-problem warnings
Some bugs don’t crash. It flags unexpected None, NaN or infinity results, and functions that modify their own arguments.


values = []  → returned None
scores was modified
  before [3, 1, 2]  after [1, 2, 3]


Type-hint inference
No example call? Call analyze(f) and an example is inferred from your type hints. Optional parameters get a None probe.


analyze(average)
# average(xs=[1, 2, 3], scale=1.5)
scale = None → TypeError
